# 子工作项(Sub-item)

## 作用

把一个大需求拆成多个小工作项。每个子项独立运行、独立分支、独立 MR,便于分别评审和合并。

## 与父项的关系

- **独立**:运行状态、git 分支、MR 都各自独立;状态不会自动联动,需手动推进。
- **分支基线**:
  - 父项有工作分支 → 子项从**父项分支**切出,MR 指向父项分支(堆叠开发)。
  - 父项没有分支(如调研、设计类)或已合并 → 子项从项目 `base_branch`(通常是 main)切出。
  - 父项是实现类、进行中、还没有分支,且子项依赖它的代码 → 子项运行会**阻塞**,等父项产出分支。
- **上下文**:子项运行时能看到父项的标题、描述、评论;父项能看到直接子项的标题和状态。

## 使用建议

- **只做拆分**:父项当容器,子项各自从 main 切出,分别合并到 main。
- **有依赖**:先让父项产出分支,再启动子项;**先合并父项,再合并子项**,父项合并后把子项 MR 的目标改回 main。

## 注意

- agent 不会自动创建子项,拆分由人来做。
- 一个工作项只对应一个分支和一个 MR,需要多个就拆成多个子项。
